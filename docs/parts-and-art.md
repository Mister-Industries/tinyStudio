# Parts & art — where they live and how to edit them

Every component you can drop into the Circuit view — the tinyBoards, the
resistors and LEDs, the SparkFun packs — is a folder of plain files in the
**[tinyparts](https://github.com/Mister-Industries/tinyparts)** repo. The art is
real `.svg` files you can open in Illustrator. This page is the map.

## Where things are

| What | Lives in | Edit it with |
| --- | --- | --- |
| **tinyBoard art** (tinyCore, tinyGlow, tinyProto, tinySniff, tinySpeak, tinyDisplay) | `tinyparts/packs/tinyboards/parts/<board>/breadboard.svg` | Illustrator / any SVG editor |
| **Core parts** (resistor, LEDs, buttons, sensors…) | `tinyparts/packs/core/parts/<type>/breadboard.svg`, `schematic.svg`, `icon.svg` | Illustrator / any SVG editor |
| A part's name, size, pin list, buses | `…/parts/<type>/part.json` | a text editor |
| Palette tile | `icon.svg` in the part folder (falls back to `breadboard.svg`) | Illustrator |
| **Optional packs** (SparkFun, Arduino, Adafruit…) | `tinyparts/packs/<pack>/parts/*.json` — one file each, SVG embedded | run `node scripts/parts-tool.mjs explode --pack <pack>` first to turn them into folders |
| The copy built into the app | `tinyStudio/src/renderer/src/assets/tinyparts/` | **don't** — generated by `npm run parts:sync` |
| Updates downloaded from GitHub | the app's parts cache (IndexedDB in the app's data folder) | nothing to edit |
| Edits saved "on this computer" | the app's saved parts (IndexedDB in the app's data folder) | the Parts editor |

tinyparts is sitting next to tinyStudio on disk: `Documents/GitHub/tinyparts`.

## How a part reaches the app

The app has four sources. When two of them have the same part, the one higher in
this list wins:

1. **This computer.** Saves from the Parts editor ("Save on this computer"),
   `.fzpz` drops. Only you see them. *Reset to default* removes one.
2. **Your tinyparts checkout**: whenever a dev server is running
   (`npm run dev` or `npm run dev:web`) and tinyparts is cloned next to
   tinyStudio. Loaded straight from disk and reloaded when a file changes.
3. **GitHub.** At launch (at most every 15 minutes) the app asks GitHub whether
   tinyparts changed. Only changed files download, and they're kept for offline
   use.
4. **Built in.** The snapshot compiled into the app. Always there, offline too.

So pushing to tinyparts updates **everyone** on their next launch, with no app
release. Nobody sees your work until you push it. A person with a local edit of
a part keeps seeing their edit until they reset it.

## Editing art in Illustrator

1. Open `tinyparts/packs/tinyboards/parts/tinycore/breadboard.svg` (or any part's
   `.svg`).
2. Edit anything you like: colours, components, silkscreen.
3. **Pins are shapes named `pin-<NAME>`.** In the Layers panel you'll see
   objects like `pin-GND`, `pin-D8`, `pin-A.5`. Each pin's position is the centre
   of that shape. Move the shape and the pin moves with it. Don't rename them:
   saved circuits connect to pins by name.
4. Save back to the same file:
   - **File → Export → Export As… → SVG**, or **File → Save As → SVG**
   - Styling: *Internal CSS* (any option works). Fonts: *SVG*. Images: *Embed*.
   - **Object IDs: Layer Names** ← this keeps the `pin-…` names
   - Decimal: 2 or more. Minify: off. Responsive: either.

You don't need to worry about:

- **Size.** The part's real size comes from `width`/`height` in `part.json` (the
  boards are `1.9in`), and the art is fitted into that box, whatever Illustrator
  writes on the root `<svg>`.
- **Gradient and class names.** Illustrator names every file's gradients
  `SVGID_1_` and styles `.st0`. The app prefixes them per part so two parts
  can't repaint each other.
- **Illustrator renaming ids.** `pin-3V3.2` coming back as `pin-3V3_x2E_2`, or
  duplicates as `pin-GND_1_`, is decoded.

### See it live while you work

1. Keep tinyparts cloned next to tinyStudio (`Documents/GitHub/tinyparts`).
2. Start a dev server in tinyStudio: `npm run dev` (desktop app) or
   `npm run dev:web` (browser). It prints
   `tinyparts: serving parts live from …`.
3. Open a project's **Circuit** tab. Save in Illustrator and the canvas and
   palette update within a second. A toast tells you, and warns if a pin went
   missing (for example, an export without *Object IDs: Layer Names*).

There's nothing to switch on, and no `npm run parts:sync` while you work.

- **A checkout somewhere else:** start the dev server with `TINYPARTS_DIR`
  pointing at it. In the desktop app you can also use Parts Packs →
  **Developer · live tinyparts → Choose folder…**.
- **Seeing the shipped parts instead:** use the ✕ in that panel. **Turn on**
  brings live parts back.
- **Restart after changing Vite config.** A dev server started before this
  feature existed won't serve tinyparts.
- Builds and the released app never read your checkout. They use the built-in
  snapshot and GitHub.

## Pins

A view's `pins` in `part.json` can be written three ways:

```jsonc
"pins": ["GND", "3V3", "A5"]           // read positions from pin-GND, pin-3V3… in the SVG, in this order.
                                       // A listed pin missing from the art is reported.
// (omitted)                           // every pin-* shape in the SVG is a pin, in file order
"pins": { "Pin 0": [0.96, 3.93] }      // fixed positions in px @ 96 DPI; the SVG's ids are ignored
```

- **Move a pin:** move its shape in the art.
- **Add a pin:** draw a shape, name it `pin-NEW`, and add `"NEW"` to the list.
- **Rename or remove a pin:** avoid it. Circuits people have saved reference pins
  by name.
- The Core parts came from Fritzing and use fixed positions (the object form).
  Their Fritzing ids don't follow the `pin-` convention. To make one follow its
  art, rename its pin shapes `pin-<name>` and switch `pins` to the list form.

## Adding a new part

**From the command line:**

```bash
npm run parts:new -- my-sensor --pack core --label "My Sensor"
```

This creates `tinyparts/packs/core/parts/my-sensor/` with a `part.json` and a
starter `breadboard.svg` (two pins, `pin-1` and `pin-2`), and lists it in
`pack.json`. Replace the art, and it appears in the app (with a dev server
running) as soon as you save.

**From the app** (with a dev server running): components rail **+** →
**Upload SVG…** (pins named `pin-*` place themselves) → **Save to tinyparts**,
picking the pack.

A folder you copy by hand also loads in dev. It shows a warning until
`npm run parts:check -- --fix` adds it to `pack.json`.

## The Parts editor's two saves

Open it from the pencil on any palette tile.

- **Save on this computer**: for anyone. Keeps your version locally, where it
  replaces the shipped part. The header says *edited on this computer* and offers
  **Reset to default**. Parts Packs also lists every local edit.
- **Save to tinyparts**: while live tinyparts is on (any dev server). Writes `part.json` and
  the `.svg` files into the checkout. A single-file part becomes a folder part. If
  you *dragged* pins, their positions are written into `part.json` as fixed
  values. Otherwise pins keep following the art.

## Publishing

1. **Check:** `npm run parts:check` (from tinyStudio; it validates `../tinyparts`
   with the app's own loader). `--fix` repairs `pack.json`/`index.json` listings
   and tidies JSON formatting.
2. **Commit and push tinyparts.** Every install picks it up on its next launch.
   Parts Packs → **Check for updates** fetches it immediately.
3. **Before an app release:** `npm run parts:sync` in tinyStudio, then commit the
   updated `src/renderer/src/assets/tinyparts/`. New installs then start with it
   offline. It warns if tinyparts has uncommitted or unpushed changes.

Preview a tinyparts branch before merging. In the app's DevTools console run
`localStorage.setItem('tinystudio.tinyparts.source', 'Mister-Industries/tinyparts@my-branch')`
and reload, then **Check for updates**. `removeItem` switches back.

## `part.json` reference

```jsonc
{
  "type": "tinyproto",          // unique id; circuits store this — never change it
  "label": "tinyProto",         // palette name (tidied by circuit/parts/naming)
  "family": "tinyStudio",       // category / simulation keywords
  "icon": "icon.svg",           // palette tile (optional; defaults to the breadboard art)
  "buses": [["A.5", "B.5"]],    // pins wired together inside the part (optional)
  "views": {
    "breadboard": {
      "svg": "breadboard.svg",
      "width": "1.9in",         // real size: number = px @ 96 DPI, or "25mm", "1.9in"
      "height": "1.9in",
      "pins": ["GND", "3V3"],   // see Pins above
      "legs": ["anode"]         // bendable legs (Fritzing parts, optional)
    },
    "schematic": { "svg": "schematic.svg", "width": 40, "height": 20 }
  }
}
```

`pack.json` lists a pack's parts as `{ "type": "…", "dir": "parts/<type>" }`.
Older single-file parts appear as `{ "type": "…", "file": "parts/<type>.json" }`.
The repo's `index.json` lists the packs; `"bundled": true` ones (tinyboards,
core) are compiled into the app and need no install.
