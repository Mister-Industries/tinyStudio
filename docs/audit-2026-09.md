## Summary

The circuit editor and the new parts pipeline are the strongest code in the repo: a React-free core, a command store with undo, and nearly all of the 243 tests. The shell around them is what reads as unfinished. The build doesn’t pass because the backend packages were never bumped, a project’s `visual.js` runs with full access to your disk, part artwork from the internet goes into the page unsanitized, and fifteen temp files from an old sandbox mount have sat in the repo since v0.2.0. None of this is hard, but 0.4.0 shouldn’t ship until the nine items below are closed.

- **REL-1** The typecheck fails, so `npm run build:win` fails.
- **REL-2** The lockfile still pins the pre-parity tinyService; an installer would ship the old backend.
- **SEC-1** Opening someone’s project runs their `visual.js` with filesystem and shell access.
- **SEC-2** File and shell IPC take any path or URL.
- **SEC-3** Downloaded or dropped part SVGs can run script.
- **BUG-1** The CSP blocks the backend whenever it starts on a port other than 3000.
- **BUG-2** Clicking a link in a README navigates the app away.
- **REL-3** v0.3 and v0.4 work is one unlabeled commit plus 176 uncommitted changes.
- **REL-4** Bundled Fritzing art ships without the attribution its license requires.

### What’s solid and worth protecting

- `circuit/core` is pure, command-driven and undoable, and it’s tested.
- tinyparts sync compares git blob hashes, so updates download only changed files.
- GitHub device-flow sign-in lives in main, with the token in the OS keychain.
- Studio AI’s core is shared by desktop and web, path-contained, and asks before every write.
- The parts docs (`parts-and-art.md`) are genuinely usable by a designer.
- The Arduino parity work fixed real serial and detection races in a principled way.

## Release & build

Whether the branch can produce a correct installer at all.

#### REL-1: The typecheck fails, so no desktop build

_Error · Confirmed_

> **Marked:** flagged · **Outcome:** Fixed in da00e03.

20 TypeScript errors, all in `WebSocketArduinoService.ts`: `message.id` doesn’t exist, client methods return `void` instead of a request id, and `boardDetails` is missing. `build` and `build:win` run the typecheck first, so both stop. - **Fix:** Install `shared@^1.2.0` and `tinyservice@^1.1.0` (both on npm), re-run the typecheck and tests.

#### REL-2: An installer would ship the old backend

_Error · Lockfile confirmed; runtime effect inferred_

> **Marked:** flagged · **Outcome:** Fixed in da00e03: tinyservice 1.1.0, shared 1.2.0.

## Security

The app now opens other people’s projects and downloads part art from the internet, so the renderer can no longer be treated as trusted.

#### SEC-1: A project’s visual.js runs with full filesystem access

_Error · Confirmed from code_

> **Marked:** flagged · **Outcome:** Fixed in 1b44673: sketches run in a sandboxed iframe.

`VisualPreview` runs the sketch with `new Function` directly in the app’s page. That page holds `window.api.fs` (read, write, delete any path), `openPath` and the raw `ipcRenderer`. Examples and pasted GitHub repos are written to disk and opened on desktop; switching to Visual runs whatever their `visual.js` contains. A hostile sketch could write an executable and launch it.

- **Where:** `VisualPreview.tsx:87` · `preload/index.ts:22–53`
- **Fix:** Run sketches in a sandboxed iframe (`sandbox="allow-scripts"`, no same-origin) and feed serial lines by `postMessage`. It also stops p5 globals leaking into the app.

#### SEC-2: File and shell IPC take any path or URL

_Error · Confirmed_

> **Marked:** flagged · **Outcome:** Fixed in 1b44673: file IPC is limited to granted folders; open-path and open-external are allowlisted.

Every file handler in main accepts an arbitrary absolute path, including recursive delete. `open-path` hands anything to `shell.openPath`, which runs executables; `open-external` accepts any scheme, `file://` included. Any script that reaches the renderer (SEC-1, SEC-3) inherits all of it.

- **Where:** `src/main/index.ts:181–329`
- **Fix:** Check paths in main against the open workspace and app data folders; allow only `https:`, `http:` and `mailto:` for external links; `openPath` only for files the app just exported.

#### SEC-3: Part SVGs go into the page unsanitized

_Error · Confirmed from code_

> **Marked:** flagged · **Outcome:** Fixed in 1b44673: DOMPurify at every render point.

Art from GitHub packs, any index URL added under More packs, and dropped `.fzpz` files is inserted with `dangerouslySetInnerHTML`. The CSP permits inline script, so an `<image onerror=…>` inside part art runs with the app’s privileges. `parts/svg.ts` says a full sanitizer would come in M2; it never did.

- **Where:** `Canvas.tsx:1663, 1874` · `Palette.tsx:38` · `PartsEditor.tsx:452`
- **Fix:** Sanitize once when art enters the registry (DOMPurify’s SVG profile): strip scripts, event handlers, `foreignObject` and external references.

#### SEC-4: tinyService accepts connections from any website

_Warning · Configuration confirmed; reach depends on tinyService_

> **Marked:** flagged · **Outcome:** App side narrowed to the app's own origins in 1b44673, but tinyService 1.1.0 doesn't enforce it. Needs a tinyService release (release plan, Waiting on the owner).

The backend starts with `allowedOrigins: ['*']`. Any page open in the user’s browser can connect to `ws://localhost:3000` and ask it to compile, upload or talk to serial.

- **Where:** `src/main/index.ts:20–23`
- **Fix:** Allow only the desktop app, `app.tinystudio.cc` and local dev origins.

#### SEC-5: Renderer hardening is switched off

_Warning · Confirmed_

`sandbox: false`; no `will-navigate` handler; the window-open handler passes every URL to the OS; the preload exposes the whole `electronAPI` although only the title-bar buttons use it.

- **Where:** `index.ts:46–74` · `preload/index.ts:172` · `Header.tsx:55–66`

#### SEC-6: The CSP allows inline and eval’d script

_Warning · Confirmed_

> **Marked:** flagged · **Outcome:** Fixed in 1b44673: no unsafe-inline or unsafe-eval in the built app's script-src.

`'unsafe-inline'` and `'unsafe-eval'` exist to support running sketches with `new Function`. Once sketches move into an iframe (SEC-1), both can go.

#### SEC-7: The web build keeps secrets in localStorage

_Info · Confirmed; documented as interim_

The Anthropic key (`webAgent.ts:29`) and the GitHub token (`github.ts:1023–1076`) are stored in plain text. Any script injection on the web build can read both.

## Bugs

#### BUG-1: The CSP blocks the backend on any port but 3000

_Error · Likely; not reproduced_

> **Marked:** flagged · **Outcome:** Fixed in 1b44673: the CSP allows any localhost port.

`ServiceManager` now binds the first free port from 3000 to 3009, but the renderer’s CSP allows only `ws://localhost:3000`. If 3000 is taken, the backend starts fine and the app can’t reach it, so the free-port fix from A.7.8 undoes itself.

- **Where:** `src/renderer/index.html:9` · `ServiceManager.ts:211`
- **Fix:** Allow `ws://localhost:*`, or set the CSP from main with the real port.

#### BUG-2: Links in docs navigate the app away

_Error · Markup confirmed in the running web build; desktop behavior inferred_

> **Marked:** flagged · **Outcome:** Fixed in 1b44673: links open in the browser.

README links render as plain anchors without `target`. On the web, clicking one leaves the app and any unsaved edits. On desktop, with no navigation guard and a frameless window, the app window becomes that website with no way back.

- **Where:** `Markdown.tsx:211`
- **Fix:** Open links with `openExternal` or `target="_blank"`, and deny in-window navigation in main.

#### BUG-3: Studio AI loses the conversation when you leave the tab

_Warning · Confirmed from code; listed in README Known bugs_

> **Marked:** flagged · **Outcome:** Fixed in acf2f4d: the conversation lives in lib/agentChat.ts.

The chat timeline lives in component state, so it resets when the panel unmounts, while the agent keeps the old context: the model remembers a conversation the user can no longer see.

- **Where:** `AIAssistant.tsx:97`

#### BUG-4: Views write files into the project without asking

## Code critique

Where the code reads as generated rather than designed. Most of it is structure, not correctness.

#### CODE-1: A handful of files do several jobs each

_Warning_

> **Marked:** flagged · **Outcome:** Partly fixed: main-process IPC split in 1b44673, EditorPanel split in b8ca2d1. Splitting Canvas.tsx is beta step 1.

`Canvas.tsx` 2,047 lines (every gesture in one component) · `CircuitView.tsx` 1,262 · `github.ts` 1,111 · `fileCommands.ts` 935 · `WebSocketArduinoService.ts` 875 · `useArduino.ts` 794 · `SimPanel.tsx` 785 · `EditorPanel.tsx` 764 (three views, a dialog and two sketch templates as strings) · `main/index.ts` with twenty-odd inline IPC handlers.

- **Start:** Split `EditorPanel` into one file per view, move main’s IPC into modules (files, window, parts), and give each canvas tool its own gesture module.

#### CODE-2: Comments narrate history

_Warning_

> **Marked:** discuss · **Outcome:** Sweep before 0.4.0. Release plan, 0.4.0 step 9b.

Many comments explain what used to happen and why it changed (“This used to be a bare console.error…”, “It used to be inferred from…”). That belongs in commit messages. In the code it doubles the reading and is the clearest sign of session-by-session generation. Keep comments on why the code is the way it is now.

#### CODE-3: Four ways of holding state

_Warning_

> **Marked:** flagged · **Outcome:** Fixed: window globals removed in ef81025; the rule is docs/state-management.md (fa6f419).

Redux slices; React contexts for Arduino and serial; module-level stores with listener sets (parts registry, sync status, GitHub account, web agent); and globals on `window` (`__tinySerial`, `p5`). Each works; together, nobody can predict where a piece of state lives. Write down the rule and move outliers to it.

#### CODE-4: Layout by measurement and magic numbers

_Warning_

The editor height is `(size / 100) * (window.innerHeight − 92)` (`EditorPanel.tsx:225`); the Files panel width comes from measuring a toolbar divider’s screen position (`App.tsx:57–73`); the Visual view polls for `window.p5` every 200 ms. These break with font, zoom or toolbar changes. Flex layout would handle them.

#### CODE-5: Command classes that are just functions

_Info_

> **Marked:** flagged · **Outcome:** Fixed in 8edca57.

Every file command repeats the same `get dispatch()` getter around the global store, and the `undo()` methods are never called. Plain async functions (or thunks) would say the same in a third of the code.

#### CODE-6: The v2 parts registry from the spec was never built

_Info_

> **Marked:** flagged · **Outcome:** Fixed in fa6f419: the spec notes the tinyparts layers replaced registry.ts.

The circuit editor still runs on the v1 `PartDef` shape through `partsAdapter.ts` (738 lines), which calls itself glue over the legacy library. The tinyparts layer registry replaced the spec’s plan in practice. Update the spec so the next reader doesn’t go looking for a `registry.ts`.

#### CODE-7: Errors are handled differently everywhere

_Info_

> **Marked:** discuss · **Outcome:** One reportError helper and a sweep. Release plan, 0.4.0 step 9a.

Toasts in some places, `console.error` only in others, and many `catch { /* ignore */ }` blocks. Pick one helper for user-visible failures and one for diagnostics.

_Info_

> **Marked:** flagged · **Outcome:** Fixed in ef81025: src/shared/tinyservice.ts holds the port.
